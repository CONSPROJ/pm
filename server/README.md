# راه‌اندازی سامانهٔ پروژه روی سرور شخصی

همه‌چیز روی یک سرور خودتان: سایت، دیتابیس و API (Supabase متن‌باز)، فایل‌های پیوست، HTTPS خودکار و پشتیبان شبانه.
کد سایت عوض نمی‌شود؛ در پایان فقط نشانی سرور در سایت عوض می‌شود.

## ۱) چیزهایی که باید تهیه شود

| مورد | پیشنهاد |
|---|---|
| سرور مجازی (VPS) | داخل ایران · Ubuntu 24.04 · حداقل ۴ هسته، ۸ گیگ رم، ۱۰۰ گیگ SSD · آی‌پی ثابت |
| دامنه | مثلاً `company.ir` |
| دو زیردامنه | `pm.company.ir` (سایت) و `api.company.ir` (دیتابیس و فایل‌ها) |
| یک برنامهٔ SSH | روی آیفون: Termius · روی کامپیوتر: ترمینال یا PuTTY |

در پنل دامنه، برای هر دو زیردامنه یک رکورد **A** به آی‌پی سرور بسازید.

## ۲) نصب (حدود ۱۵ دقیقه)

با SSH به سرور وصل شوید (کاربر `root`) و این سه خط را بزنید (دامنه‌ها و ایمیل را عوض کنید):

```bash
git clone https://github.com/CONSPROJ/pm.git /opt/pm/site
bash /opt/pm/site/server/setup.sh pm.company.ir api.company.ir you@company.ir
```

در پایان، نشانی‌ها، رمز پنل دیتابیس و «کلید عمومی سایت» نشان داده می‌شود.
**رمز پنل را جای امن نگه دارید و در چت نفرستید.** کلید عمومی سایت محرمانه نیست.

> اگر دریافت ایمیج‌های Docker خطا داد (مسدود بودن Docker Hub)، آینهٔ دیگری بدهید:
> `DOCKER_MIRRORS="https://آینهٔ-سرویس‌دهندهٔ-شما" bash setup.sh ...`
> بیشتر سرویس‌دهنده‌های داخلی آینهٔ Docker دارند؛ نشانی‌اش را از پشتیبانی بپرسید.

## ۳) انتقال داده‌ها و فایل‌ها

```bash
bash /opt/pm/site/server/migrate.sh
```

- رشتهٔ اتصال دیتابیس فعلی را می‌خواهد: Supabase ← Project Settings ← Database ← Connection string ← URI.
  روی صفحه نشان داده نمی‌شود و جایی ذخیره نمی‌شود.
- همهٔ جدول‌ها، کاربران، رمزها (رمزنگاری‌شده)، قانون‌های امنیتی، سابقهٔ تغییرات و فایل‌های پیوست منتقل می‌شوند
  و نشانی پیوست‌ها خودکار به سرور جدید اصلاح می‌شود.
- سایت فعلی در تمام این مدت روی Supabase قدیم کار می‌کند.

## ۴) وصل کردن سایت

«کلید عمومی سایت» و دامنهٔ API را به سازندهٔ سایت بدهید تا سایت به سرور جدید وصل و منتشر شود.
Supabase قدیم چند هفته دست‌نخورده می‌ماند تا اگر مشکلی بود فوری برگردیم.

## ۵) نگهداری

| کار | چطور |
|---|---|
| به‌روزرسانی سایت | خودکار؛ هر ۵ دقیقه از گیت‌هاب گرفته می‌شود |
| به‌روزرسانی امنیتی سیستم | خودکار (unattended-upgrades) |
| پشتیبان | هر شب ساعت ۲:۳۰ در `/var/backups/pm` (۱۴ شب آخر) |
| پشتیبان بیرون از سرور | **حتماً** یک مقصد بیرونی بگذارید: `apt install rclone` و `rclone config` با نام `pmbackup` (مثلاً فضای ابری) |
| به‌روزرسانی Supabase | ماهی یک بار: `cd /opt/pm/supabase && docker compose pull && docker compose up -d` |
| دیدن وضعیت | `docker ps` و `tail /var/log/pm-backup.log` |

## بازگرداندن پشتیبان

```bash
DB=$(docker ps --format '{{.Names}}' | grep supabase-db)
docker exec -i $DB pg_restore -U postgres -d postgres --clean --if-exists < /var/backups/pm/db-YYYYMMDD-HHMM.dump
```
